These notes are about one stack: a React app wrapped with Capacitor, people signing in with Supabase Auth, subscriptions already selling on the web through Stripe, and in-app purchases going through RevenueCat so iPhone and Android unlock the same access.

Paid access drifts when each platform answers “is this person paid?” on its own. A customer subscribes on the web and meets a paywall in the iPhone app. An Android subscription lapses, but the web app still unlocks everything. Refunds, restores and account switches each update a different record. That is usually not a missing button on the paywall. It is a Supabase user, a Stripe customer, and a RevenueCat app user ID — sometimes still anonymous — that have not been attached to one entitlement.

What we write here is the work between those systems: identifying a Supabase user in RevenueCat before you trust entitlements; attaching a Stripe web subscription so it unlocks the Capacitor app; keeping access as a server decision instead of a premium flag on the device; and handling purchase, renewal, cancellation, refund, restore and transfer on one path that is safe to retry.

The first article walks through the version founders hit most often: a Stripe subscriber who opens the Capacitor iPhone app and sees a paywall. We stay on this stack on purpose. Native Swift or Kotlin, Flutter and React Native apps are outside what we cover, and so are rebuilds or a move to new accounts.
